# Весёлая ферма

Небольшая браузерная ферма в духе «Весёлой фермы» (Farm Frenzy). Игра открывается на компьютере и на телефоне: поле, куры, яйца, склад, грузовик и магазин. Сервера нет — уровень и монеты хранятся в `localStorage` этого браузера.

## Почему Vite и TypeScript

Исходники разложены по модулям (сущности, цикл, ввод, интерфейс, конфиг уровней), а TypeScript не даёт перепутать яйцо с молоком, когда позже добавится корова. Vite собирает это в обычную статику в папке `dist/` — без бэкенда и без рантайм-зависимостей. В конфиге стоит `base: './'`, поэтому одни и те же файлы открываются и локально, и с адреса проекта на GitHub Pages (`/farm-game/`).

## Как запустить локально

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Откройте http://localhost:5173 . Файл `index.html` напрямую из папки не запустится: браузер блокирует ES-модули с `file://`.

Проверка сборки, которая уедет на Pages:

```bash
npm run build
npm run preview
```

## Как играть

Управление одно и то же мышью и пальцем. Наведения нет: всё нажимается.

1. Нажмите пустую грядку — на ней вырастет трава. Посадка тратит воду из ведра.
2. Если ведро пустое, нажмите колодец внизу поля или кнопку **Набрать воду**. Колодец наполняется сам, кнопка переливает воду в ведро.
3. Сытая курица гуляет. Когда проголодается, над ней появится «Голод», она дойдёт до травы и съест её. Через несколько секунд на поле появится яйцо.
4. Нажмите яйцо — оно попадёт на склад. Место на складе ограничено. Если склад полон, сначала продайте товар.
5. **Продать** вызывает грузовик и обменивает весь склад на монеты.
6. **Магазин** продаёт ещё кур, если хватает монет и места на поле.
7. Сверху написана цель уровня. Когда она выполнена, откроется экран перехода. Монеты переносятся дальше.
8. **Заново** (два нажатия подряд) начинает игру с первого уровня и обнуляет монеты.

Сейчас три уровня: собрать 8 яиц, заработать 200 монет продажами, собрать 16 яиц.

## Как устроен проект

- `src/game/config/levels.ts` — уровни: цель, поле, склад, вода, цены, магазин.
- `src/game/config/animals.ts` — животные. Курица несёт яйца, корова уже описана и рисуется, но на уровни пока не выведена.
- `src/game/config/products.ts` — продукты.
- `src/game/entities/` — поле и животные.
- `src/game/loop.ts`, `src/game/input.ts` — кадры и нажатия (мышь и палец через Pointer Events).
- `src/game/Game.ts` — правила: посадка, кормление, сбор, продажа, победа.
- `src/ui/hud.ts` и `src/style.css` — интерфейс.
- `src/game/save.ts` — сохранение уровня, монет, прогресса цели, склада, числа животных и воды.

## Как добавить уровень или животное

Новый уровень — ещё один объект в массиве `LEVELS`. Цель бывает двух видов:

```ts
{ kind: 'collect', product: 'egg', count: 12, text: 'Собрать 12 яиц' }
{ kind: 'earn', coins: 300, text: 'Заработать 300 монет' }
```

Корова уже есть в каталоге. Чтобы она появилась на уровне, добавьте её в этот уровень и цену молока:

```ts
startingAnimals: [{ id: 'cow', count: 1 }],
shop: [
  { id: 'chicken', price: 60 },
  { id: 'cow', price: 150 },
],
prices: { egg: 10, milk: 25 },
```

Для совсем нового животного нужно: id в `types.ts`, запись в `animals.ts`, продукт в `products.ts` и ветка в `render.ts`.

## Публикация на GitHub Pages

В репозитории есть workflow `.github/workflows/pages.yml`. Он запускается при пуше в `main`, собирает проект и выкладывает `dist/`. Шаг **Setup Pages** включает сайт сам (`enablement: true`), если Pages ещё не создан.

Если запуск всё равно падает с «Get Pages site failed», включите источник вручную:

1. Откройте репозиторий на GitHub.
2. Вкладка **Settings**.
3. Слева, в разделе **Code and automation**, пункт **Pages**.
4. В блоке **Build and deployment** откройте список **Source**.
5. Выберите **GitHub Actions** (не «Deploy from a branch»).

После этого откройте вкладку **Actions**, провалившийся запуск **Deploy to GitHub Pages** и нажмите **Re-run all jobs**. Ссылка на игру появится в блоке **deploy** и на странице Settings → Pages:

`https://mariazhigar.github.io/farm-game/`

Если первый запуск пишет, что деплой ждёт подтверждения: **Actions** → **Deploy to GitHub Pages** → **Review deployments** → **github-pages** → **Approve and deploy**.

Если workflow сразу красный из‑за прав `GITHUB_TOKEN`: **Settings** → **Actions** → **General** → **Workflow permissions** → **Read and write permissions** → **Save**, затем перезапустите workflow. Для публичного репозитория обычно хватает прав, которые уже указаны в самом файле workflow.
